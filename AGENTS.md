# AGENTS.md

## Project overview

**Howdy** is a WordPress plugin boilerplate by [Syntatis](https://github.com/syntatis).

It scaffolds a modern WordPress plugin with PSR-4 autoloading, a couple of Gutenberg block examples, a React-based settings page, and pre-configured tooling for linting, PHP dependency scoping, and i18n.

## Directory structure

```
app/                 # PHP classes (PSR-4, namespace PluginName)
  Plugin.php         # Plugin entry point (activation, deactivation, service iterator)
  Blocks.php         # Registers custom Gutenberg blocks from dist/assets
  SettingPage.php    # Example admin settings page (REST-aware)
inc/
  bootstrap/app.php  # Boot file loaded by plugin-name.php
  languages/         # Translation POT file
  views/             # PHP view templates (BladeOne-compatible)
src/
  dynamic-block/     # Example dynamic block (server-rendered via render.php)
  static-block/      # Example static block (save.js based)
  setting-page/      # React admin settings page (Page.jsx, useSettings.js)
dist/
  assets/            # Compiled JS/CSS output (git-ignored, generated by wp-scripts)
vendor/              # Composer dependencies (scoped via PHP-Scoper)
```

## Code style guidelines

### PHP
- Use **PHP 7.4+** with strict types (`declare(strict_types=1)`).
- Follow **PSR-4** for class autoloading and namespaces.
- Follow **PSR-12** as the base coding style, and refer to `phpcs.xml.dist` for the additional rules.
- Follow **SOLID** principles with some common design patterns like "Decorator", "Facade", "Adapter", etc. when applicable to ensure maintainable and testable code.

#### Creating a new feature

For new feature, create a new class in `app/` and register it in `Plugin.php` via the service iterator. For example:

```php
<?php

declare(strict_types=1);

use PluginName\Blocks;
use PluginName\SettingPage;
use PluginName\MyNewFeature; // Import your new feature class.

final class Plugin implements IteratorAggregate
{
  /**
   * ...existing codes...
   */

  /**
   * Return a list of object to initialize.
   *
   * @return Traversable<object>
   */
  public function getIterator(): Traversable
  {
    yield new Blocks();
    yield new SettingPage();
    yield new MyNewFeature(); // Add your new feature class here.
  }

  /**
   * ...existing codes...
   */
}
```

#### Creating a new admin view

For rendering a view on the admin page, create a new PHP file in `views/` directory, and load it via `include` or `require` in the appropriate class or function. For example, to render a settings page:

```php
add_submenu_page(
  'options-general.php', // Parent slug.
  __('Plugin Name Settings', 'plugin-name'),
  __('Plugin Name', 'plugin-name'),
  'manage_options',
  'plugin-name',
  static fn () => include_once PLUGIN_DIR . '/inc/views/setting-page.php',
);
```

#### Loading assets

For loading assets, use `wp_enqueue_script()` and `wp_enqueue_style()` with the version and dependencies from the `*.asset.php` file generated by `wp-scripts`. For example:

```php
$assets = PLUGIN_DIR . '/dist/assets/setting-page/index.asset.php';
$assets = is_readable($assets) ? require $assets : [];
$version = $assets['version'] ?? null;
$dependencies = $assets['dependencies'] ?? [];

wp_enqueue_script(
  'plugin-name',
  plugin_dir_url(PLUGIN_FILE) . '/dist/assets/setting-page/index.js',
  $dependencies,
  $version,
  true,
);
```

## Build and test commands

| Command | Notes |
|---|---|
| `npm run start` | Uses wp-scripts with custom webpack config |
| `npm run build` | Sets `NODE_ENV=production` |
| `npm run lint:js` | ESLint via wp-scripts |
| `npm run lint:css` | Stylelint via wp-scripts |
| `npm run format` | Prettier via wp-scripts |
| `composer lint` | Lint PHP files via [PHPCS with `phpcs.xml.dist` ruleset](https://github.com/syntatis/phpcs-ruleset) |
| `composer format` | Fix linting issues via PHPCBF |
| `composer make-pot` | Generates POT file for translation via [wp-i18n](https://developer.wordpress.org/cli/commands/i18n/) |
| `composer scope` | Run PHP-Scoper prefixing via [codex-companion](https://github.com/syntatis/codex-companion) |
| `composer build` | Runs scope + make-pot |
| `composer zip` | Creates a zip file of the plugin for distribution |

It's generally recommended to run the following commands:

-  `npm run lint:js`, `npm run lint:css`, and `composer lint` and make the necessary fixes before committing code.
-  `npm run build` and `composer build` before creating a zip file for distribution.
